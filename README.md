# the-hardware-ai — Synqit CAD

Text-to-CAD in the browser, branded Synqit, running on our Azure OpenAI
deployment. Type "a phone stand with a cable slot", get an editable 3D model
with sliders and an STL. It is built on an upstream open-source text-to-CAD
project (GPL-3.0, see `app/NOTICE.md`) plus our competitor research and a
feasibility plan for Synqit.

## How the two engines fit together

Synqit (electronics: schematic, PCB, BOM, firmware, build guide) and Synqit CAD
(`app/`, 3D with sliders) are one product joined by **queries, not pictures**:
the Synqit backend answers `GET /projects/{id}/cad-brief` with the board as
facts and an OpenSCAD `synqit_board()` prelude; the studio inserts it (Board
button or `?project=<id>`) and the agent builds the enclosure around real
holes, parts and connector openings. After every build the studio measures the
model (bounding box, bodies) and hands the numbers back to the agent before it
looks at any render. The Synqit editor has a **Studio** tab that embeds the
studio for the current project. Full design and the verbs / nouns / queries
rule: `docs/INTEGRATION.md`. The Synqit side lives in the `synqit/` submodule
(branch `cad-sso`): `git submodule update --init` after cloning.

## Run it in 10 minutes

You need three things installed. Everything else is downloaded by the scripts.

1. **Node 22** (20.19+ also works): https://nodejs.org
2. **Docker Desktop**, started and showing "running": https://www.docker.com/products/docker-desktop
3. **Git** and access to this private repo (ask the owner to add you as a collaborator)

And one secret from the repo owner over WhatsApp: the **Azure OpenAI key**
(resource name `aatreus`). That is the only credential. Supabase keys are
generated on your machine; the guest login is generated by the script.

```bash
git clone https://github.com/eklavya2201/the-hardware-ai.git
cd the-hardware-ai/app
npm ci --ignore-scripts
node scripts/bootstrap.mjs --azure-key PASTE_THE_KEY_HERE
npm run dev
```

Open **http://localhost:3000/cad**. You are signed in automatically as a guest
(no-auth mode). Type a prompt, for example:

```
A wall-mount holder for a 65 x 120 mm phone: 3 mm walls, 15 mm deep pocket,
open top, two countersunk M4 screw holes on the back plate, and a 12 mm slot
at the bottom for the charging cable.
```

Within about a minute you should see the model, a slider panel on the right,
and an STL button. Drag a slider: it recompiles in the browser with no AI call.
More prompts, including a hard one, are in `docs/TEST_PROMPTS.md`.

First `bootstrap` run takes 2 to 3 minutes because Supabase pulls 13 Docker
images. Later runs are seconds.

### After a reboot

Docker Desktop must be running, then in `app/`:

```bash
npx supabase start
npm run dev
```

### What works and what does not (locally)

| Feature | Status |
|---|---|
| Prompt → OpenSCAD → 3D model, sliders, STL / SCAD / DXF export | works (GPT-5.1 on Azure) |
| Follow-up edits in the same conversation | works |
| Multi-view screenshot check by the agent | works |
| Sign-in: guest auto login | on by default |
| Sign-in: email + password, Google, "Continue with Synqit" | in the code, hidden while guest mode is on; see `docs/LOCAL_SETUP.md` |
| Mesh / "Creative" mode (image → mesh) | needs a fal.ai key, not wired |
| Conversation titles by AI | needs an Anthropic key, otherwise "New Conversation" |
| Billing | bypassed in local mode |

### Troubleshooting

- `Docker is not running` from bootstrap: start Docker Desktop, wait for the whale icon, rerun.
- `.env.local already exists`: rerun with `--force`, or edit the file by hand.
- Port 3000 or 54321 busy: stop whatever uses it (`npx supabase stop` for an old stack).
- The model answers but nothing renders: open the browser console; OpenSCAD-WASM needs a browser with WebAssembly and WebGL (Chrome, Edge, Firefox are fine).
- `401` / `insufficient tokens`: `ENVIRONMENT="local"` is missing from `.env.local`.
- Azure errors mentioning the deployment: the key is for resource `aatreus` with a deployment named `gpt-5.1`; another resource needs `--azure-resource <name>` and a deployment with the same name.

## Deploy for testers (Render)

`render.yaml` is a Render Blueprint for the studio (`app/`), talking to a hosted
Supabase project and to Synqit production for boards. Step by step, including
the two human-only parts (creating the Supabase project, filling secrets on
Render): `docs/DEPLOY_RENDER.md`. Testers open `https://<service>.onrender.com/cad`,
no login (guest mode), and see their own Synqit boards if they are signed in
at synqit.in in the same browser.
